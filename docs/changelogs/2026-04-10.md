## 问题记录

### 1. YAML 配置 columns 键名问题

**现象**: 前端页面未根据 `isList`、`isQuery` 配置正确生成列表和查询条件

**原因**: YAML 配置中 `columns` 的键名使用了 Java 驼峰命名（如 `deviceType`），而代码生成器需要数据库下划线命名（如 `device_type`）

**解决**: 将 `columns` 下所有键名改为下划线命名后重新生成代码

```yaml
# 错误: deviceType: ...
# 正确: device_type:
#         javaField: deviceType
#         isList: true
#         isQuery: true
```

**适用场景**: 所有使用代码生成器的模块

### 2. E2E 测试 el-select 下拉选项超时

**现象**: Playwright 测试中点击下拉选项元素报 "element is not visible" 超时

**原因**: el-select 下拉面板渲染延迟，直接点击选项元素时元素尚未可见

**解决**: 改用键盘操作（`ArrowDown` + `Enter`）选择选项，参考 student.spec.js 成功模式

```javascript
// 错误: await authenticatedPage.click('.el-select-dropdown__item:has-text("选项")')
// 正确:
await select.click()
await authenticatedPage.waitForTimeout(300)
await authenticatedPage.press('body', 'ArrowDown')
await authenticatedPage.press('body', 'Enter')
```

**适用场景**: 所有使用 Playwright 测试 Element Plus 下拉组件的场景

### 3. E2E 测试状态 radio 选项文本不匹配

**现象**: 新增表单提交后无成功提示，查看截图发现"状态不能为空"验证错误

**原因**: `sys_common_status` 字典的 radio 选项 label 是"成功"/"失败"，而非"正常"/"停用"

**解决**: 将 E2E 测试脚本中的 `label.el-radio:has-text("正常")` 改为 `label.el-radio:has-text("成功")`

**适用场景**: 涉及状态字典的 E2E 测试

## 经验总结

1. **代码生成器配置**: YAML 中 `columns` 键名必须使用数据库字段名（下划线），`javaField` 指定 Java 驼峰名
2. **E2E 测试最佳实践**: Element Plus 下拉组件优先使用键盘操作而非直接点击选项元素
3. **字典值验证**: 编写测试前应先在系统中确认字典的 label 和 value 实际值
4. **三阶段开发流程**: 需求→生成→验证，每个阶段产出可追溯的文档和测试
