## 交互原则

### 1. 先推断→再询问→后确认

**不要** 一步步追问所有细节，而是：
1. 根据用户描述主动推断完整设计
2. 展示推断结果（含字段展示范围）并询问是否需要修改
3. 用户确认后再写入文件

### 2. 字段展示范围推断规则

**列表展示（isList）**：
- 主键 id：否
- 名称类字段（name、title）：是
- 核心业务字段（状态、类型、日期）：是
- 长文本、备注：否
- 数值类（金额、数量）：是
- 外键关联：显示名称而非 ID

**表单展示（isInsert/isEdit）**：
- 主键 id：否（新增时不展示，编辑时展示但不可改）
- 必填字段：是
- 可选业务字段：是
- 审计字段（create_time、update_by）：否
- 逻辑删除字段：否

**查询条件（isQuery/queryType）**：
- 名称类字段：LIKE 模糊搜索
- 状态/类型/字典字段：EQ 精确筛选
- 数值类：BETWEEN 范围查询
- 时间类：BETWEEN 范围查询

### 2. 文件即时生成

**DDL SQL 和 YAML 配置**：
- 确认后直接写入 `generate/config/{module}/{business}/` 目录
- 不要将完整内容输出到对话中（避免需求文档过长）
- 仅展示关键信息供用户确认

### 3. 需求文档精炼

**需求文档** 包含：
- 模块基本信息（表格）
- 核心字段说明
- 字典设计
- 功能清单
- 权限标识符

**不包含**：
- 完整 DDL SQL（已单独生成）
- 完整 YAML 配置（已单独生成）

### 4. 阶段自动流转

阶段完成后：

2. 如用户确认，自动读取下一步提示词并继续

### 步骤 5：生成 DDL SQL 并写入文件

**生成 DDL SQL**：

```sql
CREATE TABLE demo_student (
  id              BIGINT          NOT NULL      AUTO_INCREMENT COMMENT '编号',
  name            VARCHAR(50)     NOT NULL      COMMENT '学生姓名',
  sex             CHAR(1)         NOT NULL      DEFAULT '0' COMMENT '性别（0 男 1 女 2 未知）',
  age             INT             DEFAULT NULL  COMMENT '年龄',
  birthday        DATETIME        DEFAULT NULL  COMMENT '生日',
  phone           VARCHAR(20)     DEFAULT NULL  COMMENT '联系电话',
  status          CHAR(1)         NOT NULL      DEFAULT '0' COMMENT '状态（0 正常 1 停用）',
  create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  create_by       VARCHAR(64)     DEFAULT ''    COMMENT '创建人',
  update_by       VARCHAR(64)     DEFAULT ''    COMMENT '更新人',
  remark          VARCHAR(500)    DEFAULT ''    COMMENT '备注',
  del_flag        CHAR(1)         DEFAULT '0'   COMMENT '删除标志（0 正常 1 删除）',
  PRIMARY KEY (id),
  KEY idx_name (name) COMMENT '学生姓名索引',
  KEY idx_phone (phone) COMMENT '联系电话索引'
) ENGINE=InnoDB AUTO_INCREMENT=1 DEFAULT CHARSET=utf8mb4 COMMENT='学生管理表';
```

## 字段设计规范

### 命名规范

| 字段类型 | 命名规范 | 示例 |
|---------|---------|------|
| 主键 | `id` | BIGINT AUTO_INCREMENT |
| 状态/是否 | `status`, `is_*` | CHAR(1) DEFAULT '0' |
| 时间 | `*_time`, `*_date` | DATETIME |
| 外键 | `*_id` | BIGINT |
| 金额 | `*_price`, `*_amount` | DECIMAL(10,2) |

### Java 类型映射

| 数据库类型 | Java 类型 | 示例 |
|-----------|----------|------|
| VARCHAR, CHAR, TEXT | String | name, email |
| BIGINT | Long | id, user_id |
| INT, INTEGER | Integer | age, sort |
| DECIMAL, NUMERIC | BigDecimal | price, amount |
| DATE, DATETIME, TIMESTAMP | Date | birthday, create_time |
| TINYINT(1), BIT | Boolean | is_deleted |

### 表单类型 (htmlType)

| 类型 | 说明 | 是否需要 dictType |
|------|------|------------------|
| `input` | 单行文本框 | 否 |
| `textarea` | 多行文本框 | 否 |
| `select` | 下拉选择 | **是** |
| `radio` | 单选框 | **是** |
| `checkbox` | 复选框 | **是** |
| `datetime` | 日期时间选择 | 否 |
| `switch` | 开关 | 否 |

## 注意事项

1. **DDL 和 YAML 必须一致**：字段名、类型、注释要对齐
2. **字典字段必须配置 dictType**：select/radio/checkbox 都需要
3. **以下字段不配置在 YAML 中**：create_time、update_time、create_by、update_by、del_flag（代码生成器会自动处理）
4. **树表需要额外配置**：treeCode、treeParentCode、treeName
5. **主子表需要额外配置**：subTableName、subTableFkName
6. **文件路径正确**：确保 `generate/config/{module}/{business}/` 目录存在
7. **SQL 执行必须指定字符集**：所有 SQL 执行时添加 `--default-character-set=utf8mb4` 参数，避免中文乱码
8. **字段展示范围需用户确认**：列表页、新增/编辑表单、查询条件的字段范围必须展示给用户确认
9. **tplCategory 必须使用小写**：`crud`、`tree`、`sub`（大写会导致 views 页面不生成）
10. **formColNum 需询问用户**：生成 YAML 前确认表单列数（1/2/3），默认为 2
11. **columns 键名必须使用数据库字段名**（下划线命名，如 `device_type`），内部通过 `javaField` 指定对应的 Java 驼峰字段名（如 `deviceType`）
12. **新增表单 status 默认值**：前端 `reset()` 中 `status` 默认值设为 `"0"`
