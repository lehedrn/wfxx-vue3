# 05 开发实践指南

## 一、设计模式应用

### 1.1 模板方法模式

**应用场景**：Quartz 定时任务执行框架

```
AbstractQuartzJob (抽象模板)
  ├── execute()     // 定义算法骨架：前置记录 → 调用 doExecute() → 后置记录
  ├── doExecute()   // 抽象方法，由子类实现
  └── after()       // 记录执行结果到数据库

QuartzJobExecution (允许并发)
  └── doExecute() → JobInvokeUtil.invokeMethod()

QuartzDisallowConcurrentExecution (禁止并发)
  └── @DisallowConcurrentExecution
  └── doExecute() → JobInvokeUtil.invokeMethod()
```

**源码位置**：`ruoyi-quartz/src/main/java/com/ruoyi/quartz/util/`

### 1.2 策略模式

**应用场景**：数据权限过滤

| 策略 | 类 | 条件 |
|------|-----|------|
| ALL | `DataScopeAspect` | dataScope = 1 |
| CUSTOM | `DataScopeAspect` | dataScope = 2 |
| DEPT | `DataScopeAspect` | dataScope = 3 |
| DEPT_AND_CHILD | `DataScopeAspect` | dataScope = 4 |
| SELF | `DataScopeAspect` | dataScope = 5 |

### 1.3 工厂模式

**应用场景**：异步任务工厂

```
AsyncFactory (工厂类)
  ├── recordLogininfor()     // 生成记录登录日志的 TimerTask
  └── recordOper()           // 生成记录操作日志的 TimerTask
```

**源码位置**：`ruoyi-framework/src/main/java/com/ruoyi/framework/manager/factory/AsyncFactory.java`

### 1.4 单例模式

**应用场景**：
- `AsyncManager` - 异步任务管理器
- `SpringUtils` - Spring 上下文工具类

### 1.5 代理模式

**应用场景**：
- Spring AOP 为标注了注解的类/方法自动生成代理
- `@DataScope` → DataScopeAspect 代理注入 SQL 条件
- `@Log` → LogAspect 代理记录操作日志

### 1.6 观察者模式

**应用场景**：Spring ApplicationEvent

- `AsyncManager` 使用 `ScheduledExecutorService` 实现异步事件处理
- 登录成功/操作完成后触发异步日志记录

## 二、最佳实践

### 2.1 Controller 层

**✅ 推荐写法**：

```java
@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController {

    @PreAuthorize("@ss.hasPermi('system:user:list')")
    @GetMapping("/list")
    public TableDataInfo list(SysUser user) {
        startPage();  // 紧挨着查询方法调用
        List<SysUser> list = userService.selectUserList(user);
        return getDataTable(list);
    }
}
```

**关键要点**：
- 使用 `@PreAuthorize` 标注权限
- 使用 `@Log` 标注操作日志
- `startPage()` 紧跟在实际查询方法前调用

### 2.2 Service 层

**✅ 推荐写法**：

```java
@Service
public class SysUserServiceImpl implements ISysUserService {

    @Autowired
    private SysUserMapper userMapper;

    @Override
    @DataScope(deptAlias = "d", userAlias = "u")
    public List<SysUser> selectUserList(SysUser user) {
        return userMapper.selectUserList(user);
    }
}
```

**关键要点**：
- 接口与实现分离
- 数据权限通过 `@DataScope` 注解声明
- 事务方法使用 `@Transactional`

### 2.3 分页正确使用

**✅ 正确**：
```java
if (user != null) {
    startPage();
    list = userService.selectUserList(user);
}
```

**❌ 错误**：
```java
startPage();
Post post = postService.selectPostById(1L);  // 这个查询会被分页
List<User> list = userService.selectUserList(user);
```

**原因**：PageHelper 只对紧跟其后的第一个查询生效。

## 三、常见陷阱

### 3.1 PageHelper 线程变量污染

**陷阱**：调用 `startPage()` 后未消费分页参数，导致后续查询被意外分页。

**修复**：只在确定需要分页的查询前调用 `startPage()`。

### 3.2 Redis Key 冲突

**陷阱**：不同模块使用相同 Redis key 前缀导致数据覆盖。

**规范**：使用 `CacheConstants` 中定义的常量：
- `LOGIN_TOKEN_KEY` = "login_tokens:"
- `CAPTCHA_CODE_KEY` = "captcha_codes:"
- `REPEAT_SUBMIT_KEY` = "repeat_submit:"
- `RATE_LIMIT_KEY` = "rate_limit:"
- `PWD_ERR_CNT_KEY` = "pwd_err_cnt:"

### 3.3 数据权限不生效

**陷阱**：Mapper XML 中未使用 `${params.dataScope}` 拼接。

**修复**：在需要数据权限的 SQL 中添加：
```xml
<where>
    ${params.dataScope}
    ...
</where>
```

### 3.4 Token 自动续期触发频繁

**陷阱**：大量并发请求导致 Redis 频繁写入。

**说明**：Token 续期条件为 `当前时间 - loginTime >= expireTime / 2`，即剩余 15 分钟时才续期。正常使用时不会频繁触发。

### 3.5 前端动态路由缓存问题

**陷阱**：修改菜单后前端未刷新，路由仍然是旧版本。

**修复**：修改菜单后需要重新登录或手动刷新页面（F5）。

### 3.6 keep-alive 缓存不生效

**陷阱**：路由 name 与组件 name 不一致。

**修复**：确保三者一致：
1. 路由配置中的 `name`
2. Vue 组件的 `name` 属性
3. 菜单管理中的路由名称

### 3.7 定时任务反射调用失败

**陷阱**：`invokeTarget` 格式错误或目标类不在白名单中。

**修复**：
- 格式：`beanName.methodName(params)`
- Spring Bean 直接写 Bean 名称
- 普通类需带完整包名
- 目标类必须在 `Constants.JOB_WHITELIST_STR` 白名单中

## 四、代码生成最佳实践

### 4.1 DDL SQL 编写规范

```sql
-- 表名使用业务前缀（如 demo_student）
CREATE TABLE demo_student (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    name        VARCHAR(50)  NOT NULL COMMENT '姓名',
    status      CHAR(1)      DEFAULT '0' COMMENT '状态（0正常 1停用）',
    create_time  DATETIME     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time  DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) COMMENT = '学生信息表';
```

### 4.2 YAML 配置规范

```yaml
global:
  author: coderlee
  packageName: com.ruoyi.demo
  tplCategory: crud
  tplWebType: element-plus

tables:
  demo_student:
    functionName: 学生管理
    businessName: student
    moduleName: demo
```

### 4.3 模板选择决策树

```
有 parentId 字段 + 树形展示？
  ├── 是 → tree（树表）
  └── 否 → 有子表关联？
              ├── 是 → sub（主子表）
              └── 否 → crud（单表）
```

## 五、安全最佳实践

### 5.1 密码安全

- 使用 BCrypt 加密，不可逆
- 密码重试超限后锁定（默认 5 次 / 10 分钟）
- 支持密码过期引导修改

### 5.2 Token 安全

- JWT HS512 签名，防止篡改
- Redis 双重校验，支持主动注销
- 不足一半有效期自动续期

### 5.3 XSS 防护

- 请求级别：XssFilter 过滤恶意 HTML/JS
- 响应级别：HTMLFilter 清理输出内容
- 排除特定 URL（如公告编辑需要保留 HTML）

### 5.4 SQL 注入防护

- MyBatis 使用 `#{}` 参数化查询
- 排序字段使用 `SqlUtil.escapeOrderBySql()` 过滤
- `${}` 仅用于数据权限等可控场景
