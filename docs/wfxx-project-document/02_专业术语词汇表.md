## 二、使用规范

### 2.1 命名约定

- 数据库表名使用 `sys_` 前缀（系统表）或业务模块前缀（如 `base_`、`demo_`）
- Java 类名使用 `Sys` + 业务名（如 `SysUser`）或业务模块名（如 `DeviceModel`）
- 前端 API 文件按模块存放在 `src/api/{module}/` 目录下
- 前端页面按模块存放在 `src/views/{module}/` 目录下

### 2.2 权限标识命名规则

格式：`{模块}:{资源}:{操作}`

| 操作 | 示例 |
|------|------|
| 查询列表 | `system:user:list` |
| 查看详情 | `system:user:query` |
| 新增 | `system:user:add` |
| 修改 | `system:user:edit` |
| 删除 | `system:user:remove` |
| 导出 | `system:user:export` |
| 导入 | `system:user:import` |

## 三、纠正对照表

| 常见错误叫法 | 正确叫法 | 说明 |
|-------------|---------|------|
| "Spring Security Token" | "JWT Token + Redis" | Token 由 JWT 和 Redis 共同管理，Security 只负责过滤器链 |
| "前后端统一登录" | "前后端分离登录" | 前端调 API 获取 Token，后端通过 Security 过滤器验证 |
| "Redis 存 Session" | "Redis 存 LoginUser" | 不使用传统 Session，而是将 LoginUser 对象存入 Redis |
| "数据权限是行级权限" | "数据权限基于部门范围" | 数据权限通过 DataScope 注解按部门树限制可见数据 |
| "前端控制权限就够了" | "前端辅助 + 后端校验" | 前端权限可绕过，后端接口必须再次校验 |
| "代码生成是 Swagger" | "代码生成是 Velocity" | Swagger/SpringDoc 是 API 文档工具，代码生成使用 Velocity 模板 |
