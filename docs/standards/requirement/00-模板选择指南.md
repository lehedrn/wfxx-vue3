# 需求文档模板选择指南

**最后更新**: 2026-04-09

本文档帮助项目成员根据业务复杂度选择合适的需求文档模板。

## 模板分类总览

| 模板类型 | 适用场景 | 文档篇幅 | 代码生成支持 |
|---------|---------|---------|-------------|
| [标准模板](./01-标准模板.md) | CRUD/Tree/Sub | 1-2 页 | 完整支持 |
| [报表模板](./02-报表模板.md) | 查询统计导出 | 2-3 页 | 部分支持 |
| [简单业务模板](./03-简单业务模板.md) | CRUD+ 简单规则 | 3-5 页 | 基础 + 手动 |
| [复杂业务模板](./04-复杂业务模板.md) | 工作流/复杂流程 | 多文档体系 | 基础 + 大量手动 |
| [大屏需求模板](./05-大屏需求模板.md) | 数据可视化大屏 | 3-5 页 | 不支持（手动开发） |

## 各模板详细说明

### 1️⃣ 标准模板（CRUD/Tree/Sub）

**适用场景**：
- ✅ 单表数据维护（学生管理、商品管理）
- ✅ 树形结构数据（部门管理、分类管理）
- ✅ 主子表结构（订单 + 订单明细）
- ✅ 无复杂业务流程

**文档内容**：
1. 表结构 (DDL)
2. 代码生成配置 (YAML)
3. 字典设计 + SQL 脚本
4. 功能清单 + 权限标识

**交付物**：
- DDL SQL 脚本
- ruoyi-gen-cli YAML 配置
- 字典数据 SQL
- 菜单 SQL（可选）

**生成命令**：
```bash
scripts/gen-code.sh {module} {submodule}
```

**示例**：[学生管理示例](./examples/student-crud.md)

---

### 2️⃣ 报表模板

**适用场景**：
- ✅ 数据查询统计（销售报表、考勤统计）
- ✅ 多维度数据分析（按部门/时间/类别）
- ✅ 导出功能为主，无增删改
- ✅ 复杂查询条件 + 分组聚合

**文档内容**（简化版）：
1. 需求概述
2. 数据源设计（表/视图）
3. 查询条件设计
4. 统计维度 + 指标
5. 功能清单

**交付物**：
- 统计 SQL（含 GROUP BY）
- 查询参数定义
- 接口响应示例

### 3️⃣ 简单业务模板

**适用场景**：
- ✅ 标准 CRUD + 简单业务规则
- ✅ 少量自定义接口（审核、激活、分配）
- ✅ 简单业务流程（无需工作流引擎）
- ✅ 需要数据权限控制

**文档内容**（简化版）：
1. 需求概述
2. 表结构 (DDL)
3. 业务规则（校验/状态流转）
4. 自定义接口
5. 功能清单

**交付物**：
- DDL SQL 脚本
- 业务规则说明
- 自定义接口定义
- Service 层逻辑代码

### 4️⃣ 复杂业务模板

**适用场景**：
- ✅ 复杂业务流程/工作流（多级审批、会签）
- ✅ 多状态机流转（订单状态、项目阶段）
- ✅ 跨模块业务协同（采购 + 入库 + 付款）
- ✅ 需要完整文档追溯的大型功能

**文档体系**（6 个子文档）：
1. 01-需求总文档：项目概述、系统架构
2. 02-功能说明：功能模块、依赖关系
3. 03-界面操作：页面设计、交互规范
4. 04-角色权限：角色定义、权限矩阵
5. 05-业务流程：流程图、状态机
6. 06-数据接口：DDL、API 契约

### 5️⃣ 大屏需求模板

**适用场景**：
- ✅ 数据可视化大屏展示（销售大屏、监控大屏）
- ✅ 实时数据更新展示
- ✅ 多维度数据图表展示
- ✅ 指挥中心/监控室场景

**文档内容**：
1. 需求概述（基本信息、背景、功能范围）
2. 大屏布局设计（整体布局、图表清单、交互设计）

**交付物**：
- 大屏布局设计图
- 图表清单及数据源
- 视觉设计规范

## 快速选择表

| 需求特征 | 推荐模板 | 示例 |
|---------|---------|------|
| 纯数据维护，无业务规则 | 标准模板 | 学生管理、商品管理 |
| 只读查询，统计导出 | 报表模板 | 销售报表、考勤统计 |
| 有简单状态校验 | 简单业务模板 | 文章发布（草稿/发布） |
| 有多级审批流程 | 复杂业务模板 | 请假审批、采购申请 |
| 有状态机流转 | 简单/复杂业务 | 订单管理（简单）/ 工作流（复杂） |
| 跨模块协同 | 复杂业务模板 | 供应链管理 |
| 数据可视化大屏 | 大屏需求模板 | 销售大屏、监控大屏 |

## 模板降级原则

**从高复杂度模板降级到低复杂度模板是允许的**：

- 复杂业务模板 → 简单业务模板：如果流程简化，可降级
- 简单业务模板 → 标准模板：如果业务规则简单，可降级

**从低复杂度模板升级到高复杂度模板需要评估**：

- 标准模板 → 简单业务模板：添加业务规则时需要补充文档
- 简单业务模板 → 复杂业务模板：添加复杂流程时需要重新设计
